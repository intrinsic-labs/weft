# Weft Glossary

## Core Terms

- Weft: specification language plus parser/analyzer/CLI/LSP tooling.
- Spec file: a `.weft` file with declarations and annotations.
- Declaration: top-level language construct (`type`, `service`, `enum`, `view`, or top-level annotation declaration).
- Docstring: triple-quoted prose attached to declarations/members.
- Prose reference: structured reference inside prose, e.g. `@Definition("...")` or `` `User.email` ``.

## Annotation Terms

- `@Rule`: global invariant/policy declaration.
- `@Definition`: glossary/domain term declaration.
- `@Decision`: rationale/tradeoff declaration.
- `@OpenQuestion`: unresolved design question declaration.
- `@Implements`: declaration-level link from type/service to a rule.
- `@See`: declaration-level cross-reference to another symbol.
- `@TODO`: structured work item attached to a declaration.
- `@Boundary`: integration surface annotation (`api`, `database`, `ui`, etc.).
- `@Priority`: implementation urgency (`p0`..`p3`, aliases accepted).

## Architecture Terms

- `@Role`: Clean Architecture role label (`entity`, `usecase`, `repository`, `service`, `viewmodel`, `gateway`, `dto`, `adapter`).
- `@Lifecycle`: lifetime scope (`singleton`, `session`, `feature`, `view`).
- Dependency violation: inner layer depending on outer layer in role graph.
- Lifecycle violation: invalid dependency direction by object lifetime.

## Tooling Terms

- Parser: builds AST from `.weft` source (`packages/lsp/src/parser.ts`).
- Analyzer: validates semantic references/architecture/lifecycle (`packages/lsp/src/analyzer.ts`).
- LSP: language server for editor diagnostics (`weft-lsp`).
- CLI: command-line entrypoint (`weft`).
- Contract: implementation-oriented summary generated by `weft contract`.
- Bootstrap: startup payload for downstream agents generated by `weft bootstrap`.
- Coverage: gap analysis (`weft coverage`) for open questions, unimplemented rules, etc.
